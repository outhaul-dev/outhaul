# Update Outhaul from the admin UI — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An Updates panel in Settings shows how far the server is behind `main` and updates it on a click, through a root updater that builds, swaps, restarts and rolls back on failure.

**Architecture:** A new Go package `internal/update` knows the binary's stamped commit, compares it with `main` through GitHub's compare API, and talks to the updater through files in `/var/lib/outhaul/update/`. A systemd path unit starts a root `Type=oneshot` service when Outhaul creates the request file. The service runs `deploy/update.sh`, which reuses `deploy/bootstrap.sh`'s functions. While an update is in progress, the deploy worker and the backup scheduler start no new work.

**Tech Stack:** Go 1.26 (stdlib `net/http`, `html/template`), POSIX `sh`, systemd path and service units.

**Spec:** `docs/superpowers/specs/2026-10-23-ui-update-design.md`

## Global Constraints

- Read `AGENTS.md` first. Test first: write the failing test, watch it fail for the right reason, then implement.
- Go: `go vet ./...` and `go test -race ./...` pass before a task is done.
- Shell: POSIX `sh` only. Every installer/updater test file passes under `dash`, `bash --posix` and `busybox sh`. Run `sh deploy/test/run.sh`, and shellcheck through Docker: `docker run --rm -v "$PWD:/mnt:ro" -w /mnt koalaman/shellcheck:stable -s sh --severity=warning deploy/bootstrap.sh deploy/update.sh deploy/test/*.sh`.
- **`deploy/bootstrap.sh` has an uncommitted reformat in the maintainer's working copy that must never be committed.** For every edit to it: back the working copy up to the scratchpad, `git stash push -- deploy/bootstrap.sh`, edit and commit the HEAD version, `git stash pop` (resolve any conflict in the reformat's style: one statement per line, `$((i + 1))`, `'' | x)` and ` ;;` in case arms), then check with a diff against the backup that only your change was added. New files (`deploy/update.sh`, units, tests) are not affected.
- The update request carries nothing: the updater never reads the request file's contents.
- Module path: `github.com/outhaul-dev/outhaul`. The stamp variables live in `internal/update`: `commit`, `repo`, `local`.
- Updater directory: `/var/lib/outhaul/update` (`config.Config.UpdateDir()` = `<DataDir>/update`). Files in it: `updater` (marker, contents `1`), `request`, `status`, `log`, `previous/` (rollback copies).
- `status` format: `key=value` lines, written by temp file + `mv`. Keys: `state`, `from`, `to`, `message`, `started`, `finished` (Unix seconds). States: `running`, `up_to_date`, `build_failed`, `updated`, `rolled_back`, `failed`, `not_started`.
- Timings from the spec: check cache 10 minutes, background check every 6 hours, health window 60 seconds, request pickup 2 minutes, commit list capped at 50. Plan's own value: a `running` status older than 40 minutes counts as interrupted (the service's `TimeoutStartSec=30min`).
- Copy fixed by the spec and this plan (use verbatim):
  - Installer warning: `This update includes installer changes. Updating here does not apply them; re-run the installer to get them.`
  - Traefik warning: `This update restarts Traefik: every app is unreachable for a few seconds.`
  - Confirmation: `Outhaul restarts, and the admin UI is gone for a minute or so. Apps keep running. GitHub pushes that arrive during the restart are not deployed; redeploy those apps by hand.`
  - Not set up: `Updating from the UI is not set up on this server. Re-run the installer once to set it up.`
  - Unknown build: `This build does not record its commit, so it cannot update from the UI.`
  - Ahead/diverged: `This server runs a commit main does not have. Updating replaces it with main.`
  - Busy: `Wait for the running deploy, backup or restore to finish.`
  - Held manual backup/restore: `An update is in progress. Try again when it finishes.`
  - Not started: `The updater did not start. Re-run the installer to set it up again.`
- Commits: `feat(scope): summary` / `fix(scope): summary`, body says what the user sees, ending with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

- **A second Update click (another tab, a double submit) while one runs** must not start a second update: `Request` returns `ErrInProgress` and the page says an update is running. Tested in Task 3 and Task 6.
- **The updater never starts** (path unit missing or failed): after 2 minutes Outhaul removes the request, records `not_started`, and work resumes. Tested in Task 3.
- **The updater dies or the server reboots mid-update**, leaving `state=running`: after 40 minutes it no longer holds work, and the panel says the update was interrupted. Tested in Task 3 and Task 6.
- **GitHub unreachable or rate-limited:** the panel says it could not check, Update is still offered, and the error is cached for 10 minutes instead of retried on every page load. Tested in Task 4.
- **The running commit is unknown to GitHub** (a local or rewritten commit; the compare API answers 404): treated as "a commit main does not have", Update offered. Tested in Task 4.

### Task 4: Comparing with main

**Files:**
- Create: `internal/update/compare.go`, `internal/update/compare_test.go`, `internal/update/checker.go`, `internal/update/checker_test.go`

**Interfaces:**
- Consumes: `Build` (Task 1).
- Produces:
  - `type Commit struct { SHA, Subject string; Date time.Time }`
  - `type Comparison struct { Status string; Behind int; Commits []Commit; URL string; InstallerChanged, TraefikChanged bool }` with `Status` one of `const CompareBehind = "behind"`, `CompareUpToDate = "up_to_date"`, `CompareAhead = "ahead_or_diverged"`.
  - `type Comparer struct { Client *http.Client; APIBase string }` (`APIBase` default `https://api.github.com`), `func (c *Comparer) Compare(ctx context.Context, repoURL, base string) (Comparison, error)` — calls `GET {APIBase}/repos/{owner}/{name}/compare/{base}...main` with `Accept: application/vnd.github+json`, no credentials.
  - `var ErrNotGitHub`, `var ErrUnknownBuild`.
  - `type Check struct { Build Build; Comparison Comparison; Err error; At time.Time }`
  - `func NewChecker(b Build, c *Comparer, now func() time.Time) *Checker`; `(k *Checker) Get(ctx context.Context, force bool) Check` (cached 10 minutes unless `force`; errors are cached the same way); `(k *Checker) Run(ctx context.Context)` (a forced `Get` at start and every 6 hours); `(k *Checker) UpdateAvailable() bool` (last result is `CompareBehind`).

Mapping (base = running commit, head = `main`): GitHub `identical` → up to date; `ahead` → behind, `Behind = ahead_by`; `behind` or `diverged` → ahead/diverged; HTTP 404 → ahead/diverged; any other non-200 → error. `Commits`: GitHub lists oldest first — reverse, keep 50; `Subject` is the message's first line; `Date` is `commit.committer.date`. `URL` is `html_url`. `InstallerChanged`: a changed file named `deploy/bootstrap.sh`. `TraefikChanged`: a changed file `internal/traefik/proxy.go`, or `internal/config/config.go` whose `patch` has a line starting with `+` or `-` that contains `DefaultTraefikImage`. Repository URLs: `https://github.com/{owner}/{name}[.git]` and `git@github.com:{owner}/{name}[.git]`; anything else is `ErrNotGitHub`.

Units (verbatim intent):
- `outhaul-update.path`: `[Path] PathExists=/var/lib/outhaul/update/request`, `Unit=outhaul-update.service`; `[Install] WantedBy=multi-user.target`.
- `outhaul-update.service`: `Type=oneshot`, root, `EnvironmentFile=-/etc/outhaul.env` (so `OUTHAUL_LISTEN_ADDR`, `OUTHAUL_DATA_DIR` and image overrides match the service), `ExecStart=/bin/sh /usr/local/lib/outhaul/update.sh`, `TimeoutStartSec=30min`, `After=network-online.target`.

`update_main` follows the spec's updater steps, in this order:
1. `rm -f "$UPDATE_DIR/request"`; truncate `log`; `exec >>"$UPDATE_DIR/log" 2>&1`; `LOGFILE=$UPDATE_DIR/log`; `FROM=$(build_field commit)`; `OUTHAUL_REPO=$(build_field repo)` (so `fetch_source` clones the repository the running build came from; keep the default when empty); `write_status running "$FROM" "" "updating"`; `STAGE=build`; a `trap` on `EXIT INT TERM` that runs `cleanup` and, while `STAGE=build`, writes `build_failed` (`the build failed; nothing changed. See the log.`). Being stopped mid-build (`systemctl stop`, the 30-minute timeout) therefore also records `build_failed` at once.
2. `fetch_source`; `TO=$(source_commit)`; if `TO = FROM`: `up_to_date`, exit 0.
3. Go version from `go.mod`, `maybe_add_swap` with `MemTotal`/`SwapTotal`, `cached_go_toolchain`, `build_binary`, `remove_build_swap`, `pull_images "$SRC_DIR/outhaul"` (cloudflared only when `docker container inspect outhaul-cloudflared` succeeds). The log names a Traefik image change when the new `images` output differs from the old binary's.
4. `STAGE=swap`. `systemctl stop outhaul`; `snapshot` (binary, `outhaul.service`, and `$DATA_DIR/outhaul.db` plus `-wal`/`-shm` when present, into `$UPDATE_DIR/previous/`, replacing the previous copies).
5. Install the new binary and `deploy/outhaul.service` by copying to `<dest>.new` then `mv -f` (a new inode); `systemctl daemon-reload`; `systemctl start outhaul`.
6. `new_version_healthy "$TO" "$(admin_port "${OUTHAUL_LISTEN_ADDR:-:8080}")"`: up to 60 one-second attempts of `curl -sS --max-time 2 -D - -o /dev/null "http://127.0.0.1:$port/healthz"`, true when a header line matches `X-Outhaul-Commit: $TO` (case-insensitive name, CR stripped).
7. Healthy: call `install_updater "$SRC_DIR"` when defined; `updated` with message `updated from <FROM 7> to <TO 7>`.
8. Unhealthy: capture `journalctl -u outhaul -n 20 --no-pager`; `systemctl stop outhaul`; `restore_snapshot`; `daemon-reload`; `systemctl start outhaul`; if `new_version_healthy "$FROM"` → `rolled_back` (`the new version did not become healthy; rolled back to <FROM 7>`, journal lines in the log); else `failed`, with the recovery commands in the log: `systemctl stop outhaul`, copy `$UPDATE_DIR/previous/outhaul` to `$BIN` and the database files back, `systemctl start outhaul`.
